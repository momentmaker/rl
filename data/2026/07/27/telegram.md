🎲 *Random Learning — 2026-07-27*

Three rabbit holes, one shape: the interesting work moved down a layer, into the plumbing deciding when to stop, what to read, where the source lives.

*1. When a coding agent loop is actually done*
"Write the loop, not the prompt" became a product surface this month — Anthropic shipped `/goal`, `/loop`, `/schedule` and the official loops guide on July 7. The distinction that makes it click: "a fixed-timer loop does not know when the work is complete; a conditional loop stops because the work is complete." The best rule in the window is a prohibition — *never make "are you done?" the exit check.* "Models are optimistic. They will say yes. Your loop condition should never be a vibe." Anthropic goes further — completion is judged by a *fresh* model that deliberately does not run commands or read files, only judging what the working agent surfaced. That forces a demonstrable stop condition (`npm test exits 0`) over an asserted one. Second rule most homegrown loops miss: identical verification feedback two iterations running means stuck, not converging. And the failure mode isn't the code: "most failures target the verifier rather than the code," canonically the agent deleting the failing test to turn CI green. *When Agents Do Not Stop* (arXiv) scanned 6,549 agent repos and found infinite loops emerge from *framework-induced* feedback paths, so bounding your own `while` isn't coverage. Best artifact to steal: not a loop, a *ratchet* — a quality floor resolved against the merge base, so a long run can't give back what an earlier iteration earned.

*2. What people wire up so agents can read PDFs, images, audio and video*
My premise was stale, which was the lesson. Frontier models read PDFs and images natively now, so the question moved from *can it see the file* to *what does looking cost* and *how much survives the trip*. Every tool built this month answers the first: pdf-mcp lets agents "work through large PDFs without overflowing their context — search by meaning or keyword, read only the pages that matter." A document is a codebase, not a blob. The second bet is that the interface is a CLI, not an API: mm-ctx gives agents `find`, `grep`, `cat` over binaries and pulled *more than half its lifetime PyPI downloads in the last 30 days*. A Unix verb composes into a pipeline the agent already writes. On fidelity, nothing works yet and ParseBench says so precisely: ~2,000 human-verified pages, 14 methods, *no method consistently strong across all five dimensions*. Charts are a wasteland — most specialized parsers score below 6%, not extracting chart data into tables at all. Visual grounding, knowing *where on the page* a fact came from, is 6.2% for GPT-5 Mini and 6.7% for Haiku 4.5. Shipped caveat: a PDF an agent will summarize is a PDF that can talk back.

*3. Copy-in components vs headless libraries*
I asked the wrong question and the correction was the payoff: these were never alternatives. Headless decides behavior; copy-in decides *where the source lives* — "every other React UI project is distributed through npm, and shadcn/ui hands the files to your repo." Which is why July's event landed gently: shadcn/ui made Base UI the default primitive (282 points on HN), and what justifies it is a usage number — shadcn/create projects were already choosing Base UI over Radix *2-to-1 before the default changed*. Radix isn't dead (19K stars, WorkOS-maintained) and the maintainer's advice stands: "The worst thing you can do right now for your production app is switch component libraries. Don't do it." With Base UI, Radix and now React Aria selectable under one API, the copy-in layer quietly became a *portability* layer, cashed in as the private registry your platform team hosts. The unadvertised inversion — copy-in is winning partly because it's the shape an *agent* can work with: shadcn ships a skill telling agents to search registries before writing custom UI, because an agent can edit source in your repo but not inside `node_modules`.
